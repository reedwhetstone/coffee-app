# Reflect on contributor instructions

Use session evidence to improve the instructions that matter in future work. Read AGENTS.md first; keep CLAUDE.md, GEMINI.md, and .cursorrules as pointers to it.

1. Identify a demonstrated recurring failure, durable local fact, contradiction, or stale instruction. Distinguish the cause from a transient tool failure or one-off mistake.
2. Check the canonical owner and existing references before adding a rule. Prefer repairing or deleting a conflicting instruction over creating another override. Put conditional details in a relevant reference.
3. Make only changes within the user's authorization. A request to fix instructions authorizes focused edits; do not impose a second approval step. If reflection was requested only as analysis, report recommendations without publishing them. Skill publication follows the owning platform's supported workflow, not direct file edits.
4. Preserve product ownership, credential/data safeguards, and merge boundaries. Do not turn a contextual lesson into an absolute rule, require a rule for every session error, or restate generic runtime behavior.
5. Validate references and consistency, then report meaningful changes and evidence. If there is no durable lesson, leave instructions unchanged.

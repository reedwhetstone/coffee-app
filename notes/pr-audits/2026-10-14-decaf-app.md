# Decaf app successor audit

## Outcome and boundary

Deliver ADR-019 step 3 as one complete app change: independently filter decaf,
render its status and method across first-party readers, accept the future boolean
brief criterion, and pin the published SDK/CLI with regenerated CLI reference.
The shared domain facts, filtering, and counting remain Parchment-owned. New processing choices exclude decaf labels while existing legacy selections stay visible and removable. No
database mutation, brief write support, scraper cleanup, score change, or release
flag belongs to this slice.

Origin: [ADR-019](../decisions/019-decaffeination-is-its-own-catalog-fact.md),
[Parchment #366](https://github.com/reedwhetstone/parchment-api/pull/366), and
[CLI #162](https://github.com/reedwhetstone/purveyors-cli/pull/162).

## Implementation boundary

The app stores its selected boolean in URL/filter state; omission is any, true
is decaf only, and false is no decaf. SSR, BFF refreshes, map queries, share links,
and persisted filter state must preserve false rather than treating it as empty.
The existing process-facet capability governs both the control and its counts.
Anonymous/Viewer requests are stripped or denied by the existing route boundary;
row facts remain visible. Counts are read with other active filters and, for the
selected decaf control, without its own filter so switching remains possible.

All display readers use the generated catalog facts with the ADR's transitional
legacy-label display fallback. No supplier-name inference or independent decaf
classifier is introduced. The brief parser accepts boolean `decaf` before upstream
writes are enabled; summaries and dashboard links preserve both boolean values.

One PR is the coherent delivery and rollback unit. The public release packages
must be verified available before changing consumer pins. Post-merge deployment
is the prerequisite for the next Parchment brief-write/migration slice and for
later scraper processing/score cleanup.

## Inherited invariant ledger

- **DECAF-FACT**: decaf status/method stay separate from farm process; generated
  upstream types own facts. Every display reader supports structured facts and
  transitional fallback; explicit false takes precedence over stale labels.
  Status: proven. Proof: presentation and sibling component regressions.
- **DECAF-FILTER**: any/true/false survive parse, state, share, SSR, BFF, and map
  boundaries. Invalid strings never become true. Status: proven. Proof: URL,
  store, loader, and route contract tests.
- **DECAF-ACCESS**: filter/control/counts share the process-facet gate. No counts
  leak to Anonymous/Viewer; customer API keys retain existing public-data access.
  Row facts remain visible. Status: proven. Proof: access matrix, loader stripping,
  filter-metadata and locked-control regressions.
- **DECAF-SIBLINGS**: CoffeeCard, catalog map, similar panel, supplier comparison,
  inventory overview, chat output allowlist, brief summary, and dashboard link
  consume the new facts. Status: proven. Proof: source sweep and focused tests.
- **DECAF-BRIEFS**: new boolean criteria are readable before Parchment enables
  them on write; malformed values and unknown fields remain rejected. No app
  writer is introduced. Status: proven. Proof: parser/presentation/link tests.
- **DECAF-PACKAGES**: exact published SDK/CLI pins and lockfile resolutions;
  generated CLI reference is not edited manually. Status: proven. Proof: release
  receipts, generation check, CLI reference tests, and app compilation.
- **DECAF-REPAIR**: data/process cleanup and score/tier changes are deferred under
  ADR-019 steps 4–6, owned by Parchment and scraper after this app deploys. No
  current app change may clear legacy labels or recalculate stored scores.
  Status: deferred. Proof: mutation-free app boundary and governing ADR sequence.

- **DECAF-FARM-FACET**: new processing choices list farm methods, not decaf labels;
  selected legacy values remain visible and removable, and links retain upstream
  compatibility. Status: proven. Proof: `processDisplay.test.ts`, panel selection
  and page control regressions; Parchment data/facet payloads remain untouched.

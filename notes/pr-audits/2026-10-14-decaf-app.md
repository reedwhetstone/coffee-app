# Decaf app correction audit

## Outcome and current decision

Reed requested a design reassessment of coffee-app #683 on 2026-10-14, then authorized the recommended corrections and free signed-in decaf access following the price-filter precedent. The domain separation is retained; the toolbar and failure behavior are corrected. Broader free-tier recommendations are assessed, not silently implemented.

- **Compact toolbar:** `Decaf: Any` opens the existing three choices. Selection updates shared filter state, closes the popover, and restores trigger focus. Escape and outside-pointer dismissal work. The panel is horizontally contained within viewport gutters even when the toolbar wraps.
- **Honest count failures:** an alternative-count request failure removes that control's counts rather than retaining counts constrained by its own selection. Unknown is not zero; the other decaf choice remains selectable. The shared correction also covers sibling count controls.
- **Free Viewer access:** explicit `canUseDecafFilter` is independent of detailed process facets. Signed-in Viewer/Member/Admin and customer API keys can use true/false and counts. Anonymous requests are stripped with free-sign-in copy and do not receive counts. The exact legacy base-method Decaf alias follows the same rule, including denial copy, without opening other farm processes.
- **No data repair:** no database writes, brief migration, score changes, release flags, or expansion of other website entitlements.

Direction: [ADR-005 amendment](../decisions/005-catalog-access-level-positioning.md), [ADR-019](../decisions/019-decaffeination-is-its-own-catalog-fact.md), and [free-tier assessment](../product-assessments/2026-10-14-viewer-core-filters.md).

## Delivery boundary

Parchment owns filtering, authorization and counts. The [Viewer-decaf API prerequisite, Parchment #367](https://github.com/reedwhetstone/parchment-api/pull/367), must be merged and deployed before #683. It exposes the independent capability and has a filtered-row fallback until its new aggregate-function migration is applied, so database application is not a separate feature activation step. Its migration enables the faster Viewer aggregate-count path.

SDK 0.65.0 and CLI 0.44.0 remain exactly pinned published artifacts. This access correction changes neither request shape nor the generated SDK fields the app reads, so another package release is not required.

After app deployment is verified, ADR-019's original next gates remain: Parchment brief writes/migration, then scraper label repair and score/tier dry-run review. This correction authorizes neither merge nor production data mutation.

### Limits of proof

Static checks/build used non-secret placeholder environment values. The runtime is Node 24.19.0 versus the repo's Node 22 declaration. The managed browser rejected local-network navigation, so visual checks used an isolated **offline** Chromium document with compiled component/CSS and all browser network requests blocked. These are component-render fixtures, not authenticated sessions, live catalog data, or deployed app proof. Entitlement behavior is proven by app/upstream automated tests; deployed signed-in E2E remains unverified.

The original 20cceb6 submission's 3,244-test whole-app run is historical evidence, not a claim that the whole suite was rerun for this correction. Remote CI remains pending at handoff.

## Inherited invariant ledger

- **DECAF-FACT / DECAF-SIBLINGS:** generated facts remain authoritative; explicit false and unknown method are preserved; card, map, similarity, compare, inventory and chat reader regressions pass on corrected source.
- **DECAF-FILTER:** Any/true/false survive state, URL, SSR, browser list/map and removal. New popover adds no independent filter state. URL/store/route/page tests pass.
- **DECAF-ACCESS:** **revised by accepted ADR-005/019 amendment**, not silently discarded. Decaf uses Viewer-level capability; detailed process facets remain paid. Loader, filter metadata, access matrix and lock tests prove the app boundary. Upstream deployment remains a merge prerequisite.
- **DECAF-COUNTS:** failed alternative reads are unknown, not self-filtered zeros. Both boolean selections and a sibling country-control failure are covered.
- **DECAF-FARM-FACET:** new choices exclude decaf labels; existing legacy selections remain visible/removable; exact Decaf compatibility and contradictory criteria remain faithful to Parchment.
- **DECAF-BRIEFS:** boolean reads remain accepted before writes; strict parsing, summaries, fingerprints and dashboard links retain their tests. No writer added.
- **DECAF-PACKAGES:** published exact SDK/CLI pins and regenerated reference remain unchanged; package/version guards and build pass.
- **DECAF-REPAIR:** remains deferred under ADR-019. No mutation or score repair in this PR.
